# ระบบบริหารจัดการและตรวจสอบอุปกรณ์ความปลอดภัยอัจฉริยะ (Smart Fire & Safety Cloud)
### โรงพยาบาลพยุหะคีรี จังหวัดนครสวรรค์

ระบบเว็บแอปพลิเคชันสำหรับตรวจสอบความพร้อมใช้งานของ **ถังดับเพลิง** และ **ไฟฉุกเฉิน** แบบดิจิทัล ทดแทนการจดบันทึกด้วยกระดาษ (Paper-based Tag) ป้องกันการบันทึกข้อมูลย้อนหลัง และสรุปสถานะความพร้อมให้คณะผู้บริหารโรงพยาบาลรับทราบแบบ Real-time ตามมาตรฐาน HA (Part II ENV) และ JCI FMS

## 🏥 ข้อมูลอุปกรณ์ตั้งต้นในระบบ (48 จุด)

ระบบได้ถอดข้อมูลจากผังอาคารจริงทั้ง 6 ผังของโรงพยาบาลพยุหะคีรีและปักหมุดไว้ครบถ้วนทั้ง 48 จุด:

| อาคาร / พื้นที่ | ถังดับเพลิง (`PYH-FE-`) | ไฟฉุกเฉิน (`PYH-EM-`) | รวม |
|---|:---:|:---:|:---:|
| 1. อาคารส่งเสริมสุขภาพ (HPC) | 4 | 5 | **9** |
| 2. อาคารผู้ป่วยใน (IPD) | 4 | 3 | **7** |
| 3. อาคารนิสิตคุณากร (Covid 19) | 2 | 1 | **3** |
| 4. อาคารอุบัติเหตุ ชั้นบน (ER2) | 5 | 8 | **13** |
| 5. อาคารอุบัติเหตุ ชั้นล่าง (ER1) | 8 | 5 | **13** |
| 6. ห้องเบาหวาน ตึก OPD | 2 | 1 | **3** |
| **รวมทั้งสิ้น** | **25 จุด** | **23 จุด** | **48 จุด** |

## 🚀 วิธีการเปิดใช้งานระบบ

### 1. ใช้งานแบบทดสอบทันที (Local / Offline Demo)
- ท่านสามารถดับเบิลคลิกเปิดไฟล์ `index.html` บนเบราว์เซอร์ (Chrome / Edge / Safari) ได้ทันที
- ระบบจะโหลดข้อมูลอุปกรณ์ทั้ง 56 จุดขึ้นมาให้ทดสอบ สลับดูผังอาคาร ทดลองกดตรวจเช็ก สั่งพิมพ์สติกเกอร์ QR Code และส่งออกไฟล์สำรองได้ทันทีโดยไม่ต้องตั้งค่าเซิร์ฟเวอร์

### 2. นำขึ้นโฮสติ้งฟรีบน GitHub Pages
1. นำไฟล์ทั้งหมดในโฟลเดอร์ `pyuha-safety-system` ขึ้น Repository บน GitHub
2. ไปที่ **Settings** > **Pages**
3. ที่หัวข้อ **Branch** เลือก `main` หรือ `master` แล้วกด **Save**
4. ระบบจะสร้างลิงก์เว็บไซต์ออนไลน์ให้เจ้าหน้าที่สามารถเปิดใช้งานผ่านโทรศัพท์มือถือขณะเดินตรวจได้ทันที

### 3. เชื่อมต่อกับ Google Firebase (Production Cloud)
1. ไปที่ [Firebase Console](https://console.firebase.google.com/) แล้วสร้างโปรเจกต์ใหม่
2. เปิดใช้งาน Services:
   - **Authentication**: เปิดใช้งานวิธีเข้าสู่ระบบด้วย Email/Password
   - **Cloud Firestore**: สร้างฐานข้อมูล (Test mode หรือ Production rules)
   - **Firebase Storage**: เปิดพื้นที่จัดเก็บรูปภาพหลักฐาน
3. คัดลอกค่าคอนฟิกมาใส่ในไฟล์ `firebase-config.js` แทนที่ตัวแปร `firebaseConfig`
4. ระบบจะสลับไปใช้งาน Cloud ฐานข้อมูลแบบ Real-time อัตโนมัติ

## 🛡️ ระบบสิทธิ์การใช้งาน (Role-Based Access Control)

1. **Inspector (เจ้าหน้าที่ผู้ตรวจเช็ก / ช่างซ่อมบำรุง / จป.)**:
   - ดูผังอาคารและเส้นทางจุดตรวจ
   - สแกน QR Code เพื่อตรวจเช็กตามรายการมาตรฐาน พร้อมแนบรูปถ่าย
   - ดูประวัติการตรวจเช็ก
2. **Executive (คณะผู้บริหาร / กรรมการ ENV)**:
   - ดู Executive Dashboard สรุปความพร้อม (%) และตัวชี้วัด KPIs
   - ตรวจสอบรายการอุปกรณ์ที่ชำรุดด่วน
   - ตรวจสอบและพิมพ์รายงานสรุปผลการตรวจสอบประจำงวด (Tab 6)
   - เปิดเอกสารข้อเสนอนโยบายและโครงการจัดทำระบบ (`executive_presentation.html`)

## 📑 ระบบสร้างรายงานสรุปผลการตรวจสอบเสนอผู้บริหาร (Executive Inspection Report)

อยู่ในแถบเมนู **"📑 สรุปรายงานเสนอผู้บริหาร"** ใน `index.html`:
- **ปรับแต่งข้อมูลนำเสนอ:** เลือกรอบการตรวจ (เดือน/ปี), เลือกขอบเขตอาคาร (ทั้งโรงพยาบาล 6 อาคาร หรือเฉพาะอาคาร), ระบุชื่อผู้จัดทำและผู้บริหารผู้อนุมัติ
- **ดัชนีชี้วัดความปลอดภัย (KPIs):** คำนวณ Coverage Rate (%), Readiness Rate (%), จำนวนถังดับเพลิงและไฟฉุกเฉินที่พร้อมใช้ และรายการชำรุด
- **ตารางจำแนกรายอาคาร:** แสดงอัตราความพร้อมใช้งานของทั้ง 6 อาคาร
- **บัญชีข้อบกพร่องและแผนซ่อมบำรุงเร่งด่วน (Defect Action Plan):** แจกแจงจุดชำรุด อาการผิดปกติ และมาตรการแก้ไขทางเทคนิค
- **ปุ่มจำลองการตรวจ 100% (`⚡ จำลองผลตรวจครบ 100% (Demo)`):** กดเพียงคลิกเดียวเพื่อเติมผลการตรวจเช็กครบ 48 จุด พร้อมตัวอย่างข้อบกพร่อง 3 รายการเสมือนจริง
- **ปุ่มสั่งพิมพ์ / PDF (`🖨️ สั่งพิมพ์ / บันทึก PDF (A4)`):** ตัดส่วนควบคุมออกอัตโนมัติ เหลือเฉพาะหน้าเอกสารราชการทางการ พร้อมช่องลงนามของหัวหน้างาน ENV และช่องคำสั่งการของผู้อำนวยการโรงพยาบาล

## 💾 ระบบสำรองและโอนย้ายข้อมูล (Backup & Migration)
- **Export JSON**: ดาวน์โหลดฐานข้อมูลอุปกรณ์และบันทึกผลการตรวจทั้งหมดเป็นไฟล์ `.json` เก็บไว้ในคอมพิวเตอร์
- **Import JSON**: นำไฟล์ `.json` ดังกล่าวไปนำเข้าสู่ระบบใหม่ของโรงพยาบาลได้ 100% โดยไม่ต้องลงทะเบียนใหม่หรือพิมพ์ QR Code ใหม่อีกรอบ
