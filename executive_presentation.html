เอกสารนำเสนอเชิงนโยบายและแผนปฏิบัติการดิจิทัล
ระบบตรวจสอบและบริหารจัดการอุปกรณ์ระงับอัคคีภัยและไฟฉุกเฉินอัจฉริยะ
Smart Fire & Emergency Inspection System — Phyuha Khiri Hospital
หน่วยงานนำเสนอ: งานอาคารสถานที่และสิ่งแวดล้อม (ENV) เรียนเสนอ: คณะกรรมการบริหารโรงพยาบาลพยุหะคีรี สอดคล้องมาตรฐาน: HA (Part II ENV) & JCI FMS ต้นทุนซอฟต์แวร์: 0 บาท (Free Tier Serverless)

1. บทสรุปผู้บริหาร (Executive Summary)

ความปลอดภัยต่ออัคคีภัยและระบบไฟฟ้าฉุกเฉินในสถานพยาบาลถือเป็นเกณฑ์วิกฤติต่อชีวิตของผู้ป่วยและเจ้าหน้าที่ ปัจจุบันโรงพยาบาลพยุหะคีรีมีอุปกรณ์ถังดับเพลิงและโคมไฟฉุกเฉินกระจายอยู่ตามอาคารต่าง ๆ ทั่วบริเวณโรงพยาบาล ซึ่งการตรวจสอบความพร้อมใช้งานตามรอบเดิมใช้ "ระบบลงบันทึกในใบกระดาษ (Paper Tag)" ที่หน้าถัง ส่งผลให้เกิดข้อจำกัดสำคัญ 4 ประการ ได้แก่ (1) ความเสี่ยงการบันทึกข้อมูลย้อนหลังโดยไม่ได้เดินตรวจจริง (2) กระดาษชำรุด สูญหาย หรืออ่านไม่ออก (3) เมื่ออุปกรณ์ชำรุดไม่มีระบบแจ้งเตือนช่างซ่อมบำรุงในทันที และ (4) ผู้บริหารขาดหน้าจอ Dashboard สรุปความพร้อมใช้งานแบบ Real-time

โครงการนี้จึงพัฒนา ระบบตรวจสอบอุปกรณ์ความปลอดภัยผ่านเว็บแอปพลิเคชันคลาวด์ โดยอาศัยเทคโนโลยี QR Code ประจำจุด เชื่อมโยงกับผังอาคาร (Floor Plan) และระบบฐานข้อมูล Google Firebase ทำให้เจ้าหน้าที่ต้องสแกนในสถานที่จริง แนบภาพถ่ายยืนยันสถานะ และระบบส่งรายงานสรุปให้ผู้บริหารทราบแบบเรียลไทม์ โดยมีต้นทุนค่าลิขสิทธิ์ซอฟต์แวร์ 0 บาท

100% ความถูกต้องของจุดตรวจ (No Phantom Checks) < 15 นาที ระยะเวลารับแจ้งและเปิดใบงานเมื่อพบชำรุด 85% ลดระยะเวลาจัดทำเอกสารรายงานสรุปรายเดือน 0 บาท งบประมาณค่า Server & ซอฟต์แวร์รายปี

2. การเปรียบเทียบกระบวนการทำงาน (Before vs. After Transformation)

มิติการประเมิน ระบบเดิม (กระดาษเช็กลิสต์ / Manual) ระบบใหม่ (Smart Fire & Safety Cloud)
การยืนยันการตรวจจริง เซ็นชื่อลงบัตรแขวน อาจเกิดการเซ็นล่วงหน้าหรือเซ็นย้อนหลังโดยไม่ได้ตรวจดูสภาพ สแกน QR Code ประจำจุด + บันทึกเวลา Stamp และชื่อผู้ตรวจผ่าน Cloud อัตโนมัติ
หลักฐานการชำรุด ระบุข้อความสั้น ๆ ลงกระดาษ ช่างไม่เห็นสภาพจริง ทำให้เตรียมอะไหล่ไม่ถูกต้อง ถ่ายภาพความละเอียดสูง บันทึกลง Cloud Storage ทันที ช่างเห็นปัญหาชัดเจน
การแจ้งเหตุชำรุด รอจนเจ้าหน้าที่เดินตรวจเสร็จ แล้วจึงเดินไปแจ้งช่างซ่อมบำรุง หรือรอรอบสรุปสิ้นเดือน Realtime Alert อัปเดตสถานะเป็น "ชำรุด (ISSUE)" บน Dashboard ทันที
การนำทางและจุดตรวจ อาศัยความจำของเจ้าหน้าที่ อาจตรวจตกหล่นในห้องลับตา หรือพื้นที่ห่างไกล Interactive Floor Map แผนผังปักหมุดสีเขียว/แดง นำทางตามเส้นทางเดิน
การรายงานผู้บริหาร / HA ต้องพิมพ์รวบรวมข้อมูลลง Excel ใช้เวลา 3-5 วันก่อนการประชุมหรือรอบตรวจประเมิน One-Click Report ออกรายงานสถิติ พร้อมใช้งานรับการตรวจประเมิน HA ได้ทันที

3. โครงสร้างสถาปัตยกรรมทางเทคนิค (Technical Architecture)

การออกแบบเชิงสถาปัตยกรรมแบบ Serverless: ระบบทำงานบนเว็บเบราว์เซอร์มาตรฐาน (Responsive Web) เจ้าหน้าที่สามารถใช้สมาร์ตโฟนที่มีกล้องเปิดใช้งานได้ทันทีโดยไม่ต้องดาวน์โหลดแอปพลิเคชันจาก App Store หรือ Play Store รองรับทั้งระบบปฏิบัติการ Android, iOS และเครื่องคอมพิวเตอร์สำนักงาน

1. ส่วนผู้ใช้งาน (Frontend)

  • โฮสติ้ง: GitHub Pages ให้บริการ Web Hosting ความปลอดภัยสูงด้วย HTTPS ฟรี
  • QR Code Engine: ระบบถอดรหัสภาพผ่านกล้องมือถือ (html5-qrcode)
  • Interactive Map: แสดงผังอาคารจำลองด้วย Leaflet.js ปักหมุดพิกัดอุปกรณ์

2. คลาวด์ฐานข้อมูล (Backend)

  • Cloud Firestore: จัดเก็บข้อมูลอุปกรณ์ (Assets) และประวัติการตรวจ (Inspection Logs) แบบ NoSQL Realtime
  • Cloud Storage: จัดเก็บภาพถ่ายสภาพถังดับเพลิงและไฟฉุกเฉินที่พบปัญหา
  • Security Rules: กำหนดสิทธิ์การเขียนอ่านเฉพาะผู้รับผิดชอบ

3. สรุปผลและกำกับดูแล

  • Executive Dashboard: แสดงสัดส่วนความพร้อมใช้งาน (%) อัตราการเข้าตรวจ
  • Maintenance Queue: ตารางคัดกรองอุปกรณ์ชำรุดสำหรับฝ่ายช่างซ่อมบำรุง
  • Audit Trail: ตรวจสอบย้อนหลังได้ทุกชิ้น ไม่สามารถลบประวัติการตรวจได้

4. ขั้นตอนและกระบวนการปฏิบัติงาน (4-Step Workflow)

ขั้นตอนที่ 1: การลงทะเบียนอุปกรณ์และติดรหัสประจำจุด (Asset Onboarding)

เจ้าหน้าที่เทคนิคทำการบันทึกรหัสอุปกรณ์ (เช่น PYH-FE-OPD-001), ประเภทอุปกรณ์, ตึก, ชั้น, และระบุพิกัดบนแผนผัง ระบบจะสร้างภาพ QR Code Sticker พร้อมพิมพ์ลงสติกเกอร์ชนิดกันน้ำเพื่อนำไปติดตั้งที่ตัวถังดับเพลิงและโคมไฟฉุกเฉิน

ขั้นตอนที่ 2: การเดินตรวจตามแผนที่นำทาง (Patrol Inspection via Map)

เจ้าหน้าที่เปิดมือถือเพื่อดู Interactive Floor Map ระบบจะแสดงหมุดตำแหน่งอุปกรณ์ทั้งหมดในอาคาร หมุดสีเขียวคือตรวจแล้วในรอบปัจจุบัน ส่วนหมุดสีเทาคืออุปกรณ์ที่รอดำเนินการ ทำให้ไม่เกิดการเดินวนหรือตกหล่น

ขั้นตอนที่ 3: การสแกนตรวจสอบและถ่ายภาพยืนยัน (Digital Check & Photo Proof)

เมื่อถึงจุดติดตั้ง สแกน QR Code เพื่อเปิดแบบฟอร์มตรวจสอบมาตรฐาน ทำการทดสอบเกจวัดแรงดัน, สายฉีด, คันบีบ หรือกดปุ่ม Test ไฟฉุกเฉิน หากพบสิ่งผิดปกติ ระบบจะเปิดกล้องให้ถ่ายภาพความเสียหายทันที ข้อมูลจะถูกอัปโหลดขึ้น Firebase แบบ Real-time

ขั้นตอนที่ 4: การสรุปสถานะและรายงานผู้บริหาร (Executive Reporting)

ข้อมูลประมวลผลขึ้น Dashboard ผู้บริหารทันที แสดงอัตราความพร้อมของอุปกรณ์ในโรงพยาบาล หากมีถังแรงดันตกหรือแบตเตอรี่ไฟฉุกเฉินเสื่อม ระบบจะแสดงในรายการเฝ้าระวังสีแดงเพื่อให้ฝ่ายช่างเข้าดำเนินการแก้ไขตามกำหนดเวลา SLA

5. เกณฑ์การตรวจสอบมาตรฐานความปลอดภัย (Standardized Protocols)

ประเภทอุปกรณ์ เกณฑ์มาตรฐานที่ระบบตรวจสอบ (Inspection Criteria) แนวทางปฏิบัติเมื่อพบความผิดปกติ
ถังดับเพลิง
(Fire Extinguisher)		 1. เข็มเกจวัดแรงดันอยู่ในแถบสีเขียว (Ready)
2. สลักล็อกและซีลพลาสติก (Safety Seal) อยู่ในสภาพสมบูรณ์
3. สายฉีดไม่แตกลายงา คันบีบไม่คดงอหรือเป็นสนิม
4. ไม่มีสิ่งของวางกีดขวางในระยะ 1 เมตร 		ถ่ายรูปเกจ/จุดชำรุด บันทึกระบบเป็น ชำรุด (FAIL) ช่างนำถังสำรองมาเปลี่ยนแทนทันที และส่งถังเดิมไปอัดบรรจุใหม่
ไฟฉุกเฉิน
(Emergency Light)		 1. ไฟ LED แสดงสถานะไฟเข้า (AC Power) ติดสว่าง
2. ทดสอบกดปุ่ม Test โคมไฟสว่างทั้งสองดวงไม่น้อยกว่า 30 วินาที
3. สภาพสายไฟ ปลั๊กเสียบ และโคมไม่มีรอยแตกร้าว
4. องศาการส่องสว่างชี้ไปตามแนวเส้นทางหนีไฟ 		ถ่ายรูปสภาพหลอดไฟหรือแบตเตอรี่ บันทึก ชำรุด (FAIL) ช่างดำเนินการตรวจสอบชุด Battery หรือหลอด LED ภายใน 24 ชม.

6. ประโยชน์และความคุ้มค่าต่อโรงพยาบาลพยุหะคีรี (Hospital Value & Impact)

🛡️ ด้านความปลอดภัยและการรับรองมาตรฐาน HA / JCI

  • ความพร้อมในภาวะวิกฤต: รับประกันว่าอุปกรณ์ดับเพลิงและไฟฉุกเฉินทุกชิ้นพร้อมทำงาน 100% เมื่อเกิดเหตุเพลิงไหม้หรือไฟฟ้าดับ
  • ผ่านเกณฑ์การประเมินมาตรฐาน HA: มีระบบกำกับดูแลสิ่งแวดล้อมทางกายภาพและความปลอดภัย (ENV) ที่มีหลักฐานตรวจสอบย้อนหลังได้ชัดเจน
  • ป้องกันข้อผิดพลาดจากมนุษย์: หมดปัญหาการลืมตรวจจุดอับ หรือการบันทึกข้อมูลเท็จ

⚙️ ด้านประสิทธิภาพการบริหารจัดการและงบประมาณ

  • ประหยัดงบประมาณภาครัฐ: ไม่ต้องจัดซื้อระบบสำเร็จรูปที่มีค่า License หลักแสนบาทต่อปี อาศัยระบบ Cloud ฟรีสำหรับโรงพยาบาล
  • ลดการใช้กระดาษ (Paperless): ยกเลิกการพิมพ์บัตรบันทึกและแบบฟอร์มกระดาษ ประหยัดทรัพยากรตามนโยบาย Green Hospital
  • วางแผนงบประมาณแม่นยำ: ผู้บริหารทราบอายุการใช้งานและรอบการเสื่อมสภาพของอุปกรณ์ ทำให้ตั้งงบเปลี่ยนสารเคมีหรือแบตเตอรี่ได้ล่วงหน้า

7. แผนงานการติดตั้งและเริ่มใช้งาน (4-Week Rollout Roadmap)

ระยะเวลา กิจกรรมสำคัญ (Key Milestones) ผู้รับผิดชอบหลัก ผลสัมฤทธิ์ (Deliverables)
สัปดาห์ที่ 1 สำรวจนับยอดอุปกรณ์ทั้งหมด กำหนดรหัส และติดตั้งฐานข้อมูล Firebase + GitHub ทีมงานไอที + งานซ่อมบำรุง ฐานข้อมูลอุปกรณ์ครบ 100%
สัปดาห์ที่ 2 พิมพ์และติดสติกเกอร์ QR Code ประจำอุปกรณ์ทุกจุด พร้อมปักหมุดพิกัดผังอาคาร งานอาคารสถานที่ / ช่าง อุปกรณ์ทุกชิ้นมี QR Code ประจำจุด
สัปดาห์ที่ 3 ทดสอบการเดินตรวจนำร่อง (Pilot Test) ตึกผู้ป่วยนอก (OPD) และอบรมเจ้าหน้าที่ งานความปลอดภัย (จป.) เจ้าหน้าที่ผ่านการอบรม 100%
สัปดาห์ที่ 4 เปิดใช้งานจริงเต็มรูปแบบทั่วโรงพยาบาล พร้อมนำเสนอ Dashboard ให้ผู้บริหาร คณะกรรมการ ENV / ผู้บริหาร Go-Live & Full Operation

8. ข้อพิจารณาเพื่ออนุมัติ (Executive Approval Request)

ข้อเสนอเพื่อพิจารณา: ขออนุมัติให้ดำเนินโครงการพัฒนาระบบตรวจสอบอุปกรณ์ความปลอดภัยอัคคีภัยและไฟฉุกเฉินดิจิทัล (Smart Fire & Safety Cloud) เพื่อเริ่มดำเนินการจัดทำฐานข้อมูลและติดตั้งสติกเกอร์ QR Code ตามแผนงาน 4 สัปดาห์ โดยไม่มีค่าใช้จ่ายด้านซอฟต์แวร์
